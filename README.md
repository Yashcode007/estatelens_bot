# EstateLens — property intelligence

A source-grounded research chatbot for DarGlobal developments and selected Wasalt listings. The UI includes conversational research, source/city/budget filters, a searchable source library, downloadable data, and transparent AI/provider status .

Live demo: https://estate-lens-darglobal-wasalt.jocundclout8.chatgpt.site

## Run with Docker

Requires Docker with Compose. Create `.env` from `.env.example` and set a dedicated `OPENROUTER_API_KEY`, then:

```sh
docker compose up --build -d
curl http://localhost:3000/api/health
```

Open http://localhost:3000. The image uses Node.js 22, runs as the `node` user, has a health check and installs no application dependencies. Compose uses a read-only root filesystem and drops capabilities. Without a key, matching source records remain accessible but are explicitly labeled retrieval-only.

## Local development

```sh
npm test
npm start
```

Supply the key through your shell or hosting secret manager; do not commit it. No npm install step is needed. Node.js 22 or later and Python 3.10+ for collection scripts are required.

## Architecture

```text
Public source pages
  → robots-aware HTTP collector / public web reader
  → reviewed, normalized JSON catalog with source URLs and provenance
  → structured city/source/type/bedroom/SAR-budget filters
  → BM25 lexical ranking (up to 6 records)
  → OpenRouter openrouter/free
  → cited answer + original source cards
```

The same `src/core.mjs` request handler runs in Node via `src/server.mjs` and in the hosted Cloudflare Worker generated by `npm run build`. Hosting uses a Worker, not a Docker runtime. The Docker deployment is separately built and tested; both adapters execute the same business logic.

The deployed demo uses `baidu/ernie-5.5-flash-preview:free`, verified with live requests. The portable default `openrouter/free` chooses among available free models. Only the free router and `:free` model IDs are allowed. Zero-price provider constraints prevent routing to paid token inference. The actual selected model is returned to the UI. A dedicated OpenRouter API key is still required; free availability and rate limits depend on the provider/account. The server uses a 45-second timeout and preserves evidence on provider errors.

## Data collection and provenance

The included dataset contains **12 records: 6 DarGlobal developments and 6 Wasalt listings across 7 cities**, collected on 19 November 2026 UTC (20 November in India). It is a demonstration snapshot, not a comprehensive search index.

- DarGlobal: public web-reader extraction of official project pages, manually normalized. Direct HTTP collection encountered a security challenge at robots.txt and stopped that origin.
- Wasalt: public web-reader extraction followed by successful direct HTTP scraping of the six detail pages after checking robots.txt. Each record includes the collection method, timestamp and HTML SHA-256 for the direct fetch.
- `data/collection-report.json` records the observed HTTP collection outcomes. No fabricated records or seeded example prices are used.
- Source fields are preserved, including unusually large Wasalt reported areas and conflicting DarGlobal size ranges. These are flagged for verification. Missing prices are null, never zero.
- Advertiser phone numbers and personal contact information are omitted from the published catalog. Local raw captures are ignored by Git and Docker.

To rerun collection:

```sh
python scripts/scrape.py
```

The script checks robots.txt, uses an identifiable user agent, waits at least one second between requests (or the declared crawl delay), bounds response size, extracts visible text and JSON-LD, and reports challenges/403s without bypassing them. It writes ignored `data/raw/*.json` plus `data/refresh-report.json`; it does not replace reviewed data on failures. Access can vary between requests and environments.

Normalize successful extracts into the schema in `data/catalog.json`, review field accuracy, then import:

```sh
python scripts/import_catalog.py reviewed-catalog.json
npm test
npm run build
```

The validator checks uniqueness, supported source domains, source identity, required fields, dates and positive known prices before an atomic replacement. DarGlobal refreshes still require an accessible permitted public source extraction. There is no scheduled automatic refresh.

## API

- `GET /api/health`: status, record count, snapshot date, model and whether a key is configured. Does not expose the key or prove that the provider accepts it.
- `GET /api/catalog`: public normalized snapshot and provenance.
- `POST /api/chat`: JSON `{ "message": "Show apartments in Jeddah under SAR 500,000", "history": [], "filters": {} }`.

Optional filters: `source`, `city`, `type`, `maxPrice` (known SAR prices only). Responses contain `answer`, `mode`, `sources`, resolved `filters` and, for AI answers, `model`. Modes distinguish AI output, retrieval-only, no matching evidence and provider failure. Input size and per-instance rate/concurrency limits bound demo usage. For a high-traffic deployment, add a shared durable limiter and spend controls at the gateway; the in-memory limiter does not coordinate across isolates.

## Validation

`npm test` runs 11 tests covering SAR budget/currency behavior, retrieval ranking, filters, follow-up context, missing evidence, malformed inputs, source URLs, missing credentials, free-model restrictions, the OpenRouter request contract, invalid citations and provider errors. Provider contract tests use a mock and do not establish live inference.

Docker build and runtime smoke tests cover `/api/health`, `/api/catalog` and `/api/chat`. Six live question checks passed against the deployed app; their complete answers are in `tests/results/live-validation.json`. Interactive browser QA could not run because the environment browser failed to start and the preview relay was unavailable. The redesigned HTML and embedded JavaScript were checked for successful serving and syntax, but visual browser verification remains incomplete.

## Deployment

For Sites, set `OPENROUTER_API_KEY` as a server secret and optionally `OPENROUTER_MODEL` (default `openrouter/free`). Build with `npm run build`; `.openai/hosting.json` identifies the Site. The resulting `dist/server/index.js` is a Worker ES module. Package `dist/server/index.js` with `.openai/hosting.json`, save the matching pushed source commit, and deploy that saved version.

For a Docker hosting provider, deploy the Dockerfile, expose port 3000, set the same secret in the provider dashboard and enable HTTPS. No database or persistent volume is required.

## Limitations and tradeoffs

BM25 avoids an embedding service and makes this small corpus cheap and auditable, but synonyms and multilingual retrieval are limited. A larger system should add multilingual embeddings and a hybrid index, pagination and scheduled permitted collection. Conversation context is short and held in browser memory only. Questions and relevant records are sent to OpenRouter when AI is enabled. Citation ID checks do not prove every generated statement is entailed by its source; the prompt limits answers to evidence, and source cards enable review. This is property research, not investment, legal, immigration or tax advice.
